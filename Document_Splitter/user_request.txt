# Universal Book Chapter Splitter

Split any DOCX book into **one DOCX per chapter** while preserving formatting,
images, tables, styles, headers/footers, and page settings.

## How preservation works (the key idea)

A `.docx` is a ZIP of XML parts. Instead of *rebuilding* a new document (which
loses styles, fonts, media, headers), this engine **clones the entire original
package per chapter and rewrites only `word/document.xml`**, keeping just that
chapter's body blocks plus the preserved `sectPr` (page size, margins,
header/footer references). Every other part — `styles.xml`, `numbering.xml`,
`theme1.xml`, embedded fonts, `media/*`, headers/footers, `footnotes.xml` — is
copied byte-for-byte. Result: near-perfect preservation, because nothing is
reconstructed.

## Install

```bash
pip install -r requirements.txt   # just lxml
```

## Usage

```bash
# Inspect the detection plan without writing files
python -m book_splitter book.docx --dry-run

# Split into per-chapter DOCX files (a sub-folder per book)
python -m book_splitter book.docx --out chapters_out

# Multiple books / globs, choose level, save a JSON report
python -m book_splitter "*.docx" --out chapters_out --level chapter \
    --report chapters_out/report.json

# Optional offline LLM-fallback stub for low-confidence blocks
python -m book_splitter book.docx --out chapters_out --llm heuristic

# Prove formatting was preserved
python -m book_splitter.verify book.docx chapters_out/book/
```

## CLI options

| Flag | Meaning |
|------|---------|
| `inputs` | one or more `.docx` files or globs |
| `--out` | output directory (a sub-folder per book) |
| `--level {auto,part,chapter,section}` | split granularity |
| `--llm {off,heuristic}` | optional fallback for REVIEW-band blocks |
| `--report PATH` | write a JSON detection + manifest report |
| `--dry-run` | detect and print the plan; write nothing |
| `--verbose` | debug logging |
